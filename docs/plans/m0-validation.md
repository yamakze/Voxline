# M0 真实媒体验证

状态：短样本阶段完成；长视频验证由 [VXL-045](https://github.com/users/yamakze/projects/1/views/1?pane=issue&itemId=259733484) 暂缓跟踪。短样本关联任务：[VXL-004](https://github.com/users/yamakze/projects/1/views/1?pane=issue&itemId=258840684)。

当前 Task 与原生应用验收以 [首版执行计划](voxline-v1.md) 和 [ADR-0004](../ADR/0004-task-workflow-and-native-design.md) 为准；本协议保留 ASR 样本验证边界。

## 目标与样本

验证目标 Mac 的本地转写、绝对时间轴、词级时间信息和资源占用，并与同视频 SmartSub 结果对照。模型与性能门槛经实测决定。

优先覆盖一个 30 分钟级样本和一个 120 分钟级样本，包含静音、背景音乐及连续对白。较短样本可先验证工具链，长视频覆盖由独立记录体现。

当前采用 S001 完成工具链与人工字幕校对，进入 M1。30／120 分钟验证暂缓；需要确认长视频资源、分段边界、恢复行为或支持范围时重启，使用本协议继续验证。

每个样本登记文件哈希、媒体时长、音轨 ID、语言、实际解码状态、时间起点、音频采样格式和 SmartSub 配置。私有媒体、原始字幕与完整本地路径保存在忽略的 tmp 目录；Project 回写样本编号与结果摘要。

## 验证入口

固定官方 argmax-oss-swift v1.1.0。官方 CLI 在当前 Swift 6.2.3 / Xcode 26.2 环境的 TTSKit 模块遇到 MLModelAsset 并发编译错误；M0 使用仅依赖 WhisperKit 的验证程序，复用模型加载、增量转写及 JSON/SRT 报告 API。

媒体检查与抽音频使用 AVFoundation。明确选择音轨，输出 16 kHz 单声道 PCM，并检查源时间连续性和真实输出格式。沙盒内系统媒体服务失败需要与视频解码失败区分，保留原始错误和扩大执行权限后的结果。

增量读取采用 120 秒读取与暂存、最多两个解码块缓冲及单推理 worker。v1.1.0 的读取器内部始终按 VAD 切分最多约 30 秒的模型窗口；转写策略 none 不关闭这条分块路径。真正不经过 VAD 的对照需要 fullFile + none，单独记录其内存边界。有效音频帧裁剪实验保留 SDK 原始版本，通过 SegmentSeeking 接口注入，在 DTW 前排除补零区，并记录同一识别文本的原始与裁剪对齐结果。

模型模式显式传入并记录实际加载目录；语言采用明确的自动检测配置，结果中记录检测语言。

## 记录与判断

- 模型初始化时间独立记录，包含首次下载、加载等成本；纯转写耗时另行记录。
- 转写实时系数为转写秒数除以音频秒数；不将模型下载时间混入推理实时系数。
- `/usr/bin/time -l` 的最大常驻内存记录为整进程峰值，覆盖初始化和转写；不代表单独推理峰值或整台设备的模型与系统服务占用。
- 核对输出 JSON/SRT 实际存在、段和词数量、缺失词级时间信息、时间倒置/越界、异常重叠及分段边界。
- SDK 原始 SRT 在有词级信息时按单词输出，作为诊断材料；产品字幕切分、上下文翻译和手工编辑由对应实现任务验证。
- 对照 SmartSub 的同视频、同音轨结果；对白质量通过人工听录检查，记录首尾、静音、音乐及分段边界片段。
- 单样本推理成功不自动满足长视频、Task 批处理、翻译、恢复或应用内播放校对验收。

官方 CLI 可能在文件处理失败时只打印错误；v1.1.0 的 VAD 合并路径也可能只记录分块失败并返回其余结果。验证入口传播外层转写和报告写入错误，但这不能保证 SDK 内部所有分块错误都可见。产品接入必须建立逐块失败与覆盖检查；结果还需检查实际输出内容与质量状态，不能只依靠进程退出码。
