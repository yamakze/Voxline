# Voxline 交付顺序

状态：活跃。条目的前置、Scope、Status 和验收结果统一维护于 [GitHub Project](https://github.com/users/yamakze/projects/1)。本计划只保存阶段关系，不复制进度。

| 阶段 | 条目与工作 | 退出条件 |
| --- | --- | --- |
| 需求基线 | VXL-001～004、045 | 个人工作流和样本范围明确；长验证按独立条目处理 |
| Task 基础与原生入口 | VXL-005、006、007、011、034、046、047 | 混合媒体任务可保存，参数冻结，明确音轨、模型与错误 |
| 转写与恢复 | VXL-008、009、010、012、026 | 有界音频输入、可信原始文本与时间、顺序处理、失败隔离与持久恢复 |
| 翻译与播放校对 | VXL-013～017、048 | 实际翻译可验证；媒体详情可播放编辑；三种 SRT 正确导出 |
| Mac MVP 验收 | VXL-020、047 | 本地批处理完整工作流及原生界面验收通过 |
| 原生字幕烧录 | VXL-039 | 已校对快照、所选音轨、新 MP4 与实际播放器验收 |
| 全本地翻译 | VXL-023 | Apple 语言支持与安装可见、ID 完整映射、会话与队列恢复、人工质量对照 |
| iOS 后续 | VXL-030 | 手动文件导入、原生播放与校对在目标设备通过 |

VXL-047 的队列、播放校对和视觉验收随对应能力接入，不能把其整体验收反过来作为这些能力的开发前置。iOS 构建入口可独立使用，完整交付仍在 Mac MVP 之后。

产品与页面范围见 [需求](../RFC/voxline-v1.md)，具体实施规则见 [架构](../architecture/README.md)，开发入口见 [开发工作流](../development.md)。
