# Voxline 交付顺序

状态：活跃。条目的前置、Scope、Status 和验收结果统一维护于 [GitHub Project](https://github.com/users/yamakze/projects/1)。本计划只保存阶段关系，不复制进度。

| 阶段 | 条目与工作 | 退出条件 |
| --- | --- | --- |
| 需求基线 | VXL-001～004、045 | 个人工作流和样本范围明确；长验证按独立条目处理 |
| Task 基础与原生入口 | VXL-005、006、007、011、034、046、047 | 混合媒体任务可保存，参数冻结，明确音轨、模型与错误 |
| 转写与恢复 | VXL-008、009、010、012、026 | 有界音频输入、可信原始文本与时间、顺序处理、失败隔离与持久恢复 |
| 翻译与播放校对 | VXL-013～017、048 | 实际翻译可验证；媒体详情可播放编辑；三种 SRT 正确导出 |
| Mac MVP 验收 | VXL-020、047 | 本地批处理完整工作流及原生界面验收通过 |
| 原生字幕烧录 | VXL-039 | 已校对快照、所选音轨、新 MP4 与实际播放器验收 |
| 全本地翻译 | VXL-023 | Apple 语言支持与安装可见、ID 完整映射、会话与队列恢复、人工质量对照 |
| iOS 播放校对基础 | VXL-030 | 手动文件导入、原生播放与校对在目标设备通过 |
| iOS 文件交接 | VXL-055 | 基于现有成果导出三种 SRT、分享任务并保持跨设备手动往返成果 |
| iOS 独立处理准备 | VXL-050、051、053 | 本地混合媒体 Task、模型与两条翻译路线可用；参数与平台状态明确 |
| 任务资源清理 | VXL-060 | 两平台共享删除流程，保留其他任务引用，清理失败可在重启后重试 |
| iOS 转写与顺序执行 | VXL-052、054 | 真机转写、持久检查点、失败隔离、取消与翻译暂停恢复 |
| iOS 校对补齐 | VXL-056 | 完整任务详情与播放控制，单句／选中字幕重译保留手工编辑 |
| iOS 视频输出与后台继续 | VXL-057、032 | 原生硬字幕导出；后台能力按实际系统资源接入并可恢复 |
| iOS 完整工作流验收 | VXL-031、058 | 独立处理、导出与手动交接通过真机验收，设备资源边界明确 |

VXL-047 的队列、播放校对和视觉验收随对应能力接入，不能把其整体验收反过来作为这些能力的开发前置。iOS 构建入口可独立使用，完整交付仍在 Mac MVP 之后。

VXL-031 为 iOS 功能补齐汇总项，不作为其子项前置。VXL-055 可先使用导入成果交付；VXL-050／051／053 可独立准备，VXL-052 依赖模型，VXL-054 整合实际转写与翻译。VXL-056 的播放控制和详情可先补齐，重译依赖翻译与队列。VXL-057 复用 Mac 烧录服务，VXL-032 复用持久恢复并分别验证各类后台工作。VXL-058 验收完整工作流；长样本仍由 VXL-045 独立治理。

VXL-050 的任务准备和 VXL-056 的详情／校对属于主要页面整合，采用共享领域操作与平台原生布局。界面与处理能力可分别协作：VXL-052／054 接通真实转写和批量执行，VXL-055 接通文件导出与分享；页面只能呈现已经接入的实际状态和操作。模型默认选择在任务创建时按目标设备确定，量化资源预算及系统覆盖由 VXL-058 统一验收。

产品与页面范围见 [需求](../RFC/voxline-v1.md)，具体实施规则见 [架构](../architecture/README.md)，开发入口见 [开发工作流](../development.md)。
