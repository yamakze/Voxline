# 软件包与代码架构审视

状态：活跃。当前职责和依赖只维护于 [架构](../architecture/README.md)，实施与验收统一记录于 Project。

## 结构结论

底层能力与处理编排按职责分包，应用使用同一模块和入口；平台适配通过条件编译选择。JSON Task 是成果权威来源，检查点与字幕版本规则共用。系统最近文档、iOS 设备副本及 Apple 视图会话保留真实生命周期边界。

## 后续整合点

| 条目 | 现有边界 | 接入时的收敛要求 |
| --- | --- | --- |
| VXL-050／056 | Mac 处理页面与 iOS 浏览校对入口仍有范围差异 | 共用任务准备、详情与校对主页面，平台分支只处理导航、触摸布局和原生 API |
| VXL-051／052／054 | iOS 未链接推理与 Workflow；IOSTaskLibrary 保存设备副本 | 使用既有模型和工作流能力，保留设备副本语义；不复制队列、检查点提交或编辑保护 |
| VXL-053 | Apple Translation 会话在 Mac 稳定根视图；服务配置已归入 Translation | 复用配置和协议，核验 iOS 会话生命周期；避免引入第二套服务元数据或系统下载状态 |
| VXL-057 | Media 内的烧录实现采用 macOS 条件编译 | 复用快照、时间轴、合成与导出规则，只适配原生文字渲染和文件交互 |

这些边界随对应功能真实接入时调整，不提前引入没有调用方的协议、基类或配置层。原始单媒体文档与编解码器仍用于格式迁移，不能按旧命名直接删除。完成相关整合后归档本审视，不在此记录执行进度。
