# M1 混合媒体输入与重构后持久化验证

日期：2026-10-03。环境：M4 / 16 GB，macOS 15，Swift 6.2 / Xcode 26.2。

## 交付

VXL-006 的 Task 多选入口统一接受 MP4/MOV/M4V 与 M4A/MP3/WAV，展示类型、时长、编码、语言、可解码状态和失败原因。多语言音轨必须明确选择，独立音频不要求视频轨。错误条目保留在同一 Task，其他合法条目继续准备，原文件保持引用。

MediaInspector.shared 在进程内按文件 URL、大小和修改时间复用检查。每次仍打开文件确认读权限；大小或修改时间变化后重新检查并计算哈希。确认和重新关联比较实际内容及所选音轨；新进程首次访问重新检查，不保存另一份媒体索引。修改内容同时保持大小和修改时间的情况不属于此缓存的检测保证。

准备期间的文件或书签失败转换为相应条目失败，不清空已有字幕。参数缺失、保存错误和原 Task 被修改均明确拒绝提交。取消终止未提交的检查与保存任务。

单窗口界面沿用重构后的导航和布局。TaskLibrary 删除重复写入，打开只登记，保存错误向界面传播，损坏任务不被隐藏。Task 对象驱动准备 sheet，避免新建后沿用旧任务快照。长期边界见 ADR-0006。

示例字幕、计时模拟处理和伪译文已删除。开始、重试及 API 重译在真实处理接通前明确不可用，既有字幕保留。模型本地文件显示“待加载验证”，目录存在不代表可转写。SDK 下载调用位于 VoxlineWhisperKit；完整模型安装与加载仍由 VXL-007 验收。

预览检查书签对应的文件身份，持有播放所需的沙盒访问，使用用户选定的音轨。关闭详情释放播放器、时间观察器和文件访问。完整播放、定位、编辑、偏移和导出由 VXL-015/016/017 继续验收。

## 自动检查

swift test：32 项测试、6 个测试组通过。

- M4A、MP3、WAV 检查独立音频身份，并实际读取解码后的样本。
- 文件大小变化、同大小但修改时间变化使缓存失效；确认旧身份拒绝变更文件。
- 无音轨、空文件、损坏音频、不支持扩展名和无效音轨明确失败。
- 正常音频与失败视频在同一 Task 中保存、重开和冻结参数，原字幕保持。
- 打开旧文档不写回；非法任务及原子写入失败保留最后成功保存的文件。
- 任务目录内损坏文件保留错误条目，保存失败不登记虚构成果。

MP3 样本为生成的 MPEG-1 Layer III 单声道静音帧；M4A/WAV 使用 AVAudioFile 生成。视频为既有 1 秒 H.264、英语/西班牙语 PCM 双音轨样本，无第三方片源依赖。

## 沙盒应用运行

Scripts/compile_and_run.sh debug 构建、打包、本地签名并替换旧进程通过。

同次选择 audio.m4a、audio.mp3、audio.wav、broken.mov 和 video.mov：

1. 三种音频显示 AAC、MP3、PCM 和可解码状态；视频显示 H.264、英语轨 2 和西班牙语轨 3。
2. 未选视频音轨时保存明确显示“请先选择转写音轨”。
3. 选择英语轨 2 后保存成功，详情显示 5 个媒体、0 完成、1 失败、0 句字幕，失败原因保留为空文件。
4. M4A 详情加载成功，播放时间由 0 推进至约 0.333 秒。
5. 重启后恢复同一 Task、5 个条目、失败原因和所选音轨；M4A 书签仍能加载。
6. 重启并打开媒体前后 Task 文件字节一致，SHA-256 为 347dd9661d98d5edc916b8b6e02bd62d5f2e2702d94c16c4236f49db7332ebb0。
