# ADR-0008 有界转写与原始证据

状态：已接受。日期：2026-10-03。修订：2026-10-09。对应 VXL-008／009。

## 决定

转写 Provider 消费媒体层生成的有界 PCM 块，复用唯一模型和 SDK 音频数组入口；Task 队列负责媒体与块的推进。SDK 增量加载及 VAD 并发合并不作为当前执行路径。

原始识别证据与可读字幕独立。SDK 过滤前保留文本、词元及对齐前后结果；不能通过排序或删除非空文本获得成功状态。词对齐时间无效或词文本串到相邻段，而段解码时间有效时，整窗使用段时间；段时间与真实音频窗口取交集后仍无有效时长，或置信度、覆盖异常时保留失败范围和待校时证据，由任务层显示失败并决定重试或校对。段时间可含模型补齐窗口的尾部，派生字幕结束时间裁到实际输入末端，原始证据保持。已保存的完整识别（包括末窗时间校验失败）复用同一选择规则，恢复切分无需重复识别。

## 理由

固定 SDK 的增量读取器隐含 VAD，分块结果合并可能跳过失败。媒体层已有有界输入和源时间，复用该边界能避免重复抽取与另一套分块策略。

词对齐会使用补零后的时间列，且 SDK 会过滤零时长段。真实样本已确认非空文本可能被丢弃，因此窗口范围、完整文本及失败必须成为 Provider 的显式结果。结构验证不代表识别质量或人工听录已通过。

完整 S001 中“*coughing*”“The End”等非对白短段在对齐后为零时长，而段解码时间连续有效。整块失败会让长视频因少量非对白文本无法完成；按字符比例估算会产生无法从音频验证的内部时间。回退到模型给出的段时间保留可解释来源，字幕生成后可按需校对，不把回退结果当作已人工核对。

词对齐在 Provider 边界保留一份遵循固定 SDK 规则的步长正确实现，复用 SDK 可公开调用的后处理。SDK 的内部矩阵复制把 IOSurface 行填充当作连续权重，真实 MP4 与 WAV 的相同 PCM 因尾帧数量不同产生数秒时间差。逻辑行列读取解决这一内存布局问题，无需改变源音频或维护整套推理 SDK 分支。

当前实施规则只维护在 [架构](../architecture/README.md#转写-provider)。验证、未完成范围和后续进度维护于 [GitHub Project](https://github.com/users/yamakze/projects/1)，不在本决定中复制。
