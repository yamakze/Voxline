# ADR-0004 Task 工作流与原生界面

状态：接受。日期：2026-10-02。

本决定替代 ADR-0001 的 iCloud 与单媒体首版范围、ADR-0002 的外部播放器校对目标，以及 ADR-0003 的单媒体项目根对象和重复媒体扫描策略。既有字幕正确性、持久恢复与沙盒访问规则继续适用。

## 决定

Task 作为工作流根对象，包含一批本地音视频的有序媒体条目与本次参数。参数在开始前选择、开始时冻结；媒体条目独立保存处理结果、失败原因和校对数据。使用具体名称 ProcessingTask，避免与 Swift 并发 Task 类型混淆。

Mac MVP 完成队列、转写翻译和详情播放校对。首版按顺序处理媒体，单项失败继续其余条目，失败项可明确重试。先采用本地任务存储与单一执行者，不设计跨设备执行或通用调度框架。

单媒体 SubtitleProject 可作为媒体条目的既有字幕成果迁移输入，不再是新任务的根对象。旧文档读入新任务时保留原有成果；未取得明确处理完成证据的旧数据不自动标作完成。任务列表、队列执行和单媒体详情保持清楚的数据关系。

来源在 MVP 仅为本地 MP4/MOV/M4V 与 M4A/MP3/WAV。YouTube URL 为后续条目，下载与字幕处理分开，获得本地文件后复用处理队列；不提前建立站点适配框架。

iCloud 同步、云冲突合并和同步选项暂废弃；保留 Project 记录和重启条件。平台限定 macOS、iOS。iOS 原生播放与校对在 Mac MVP 后交付，通过手动导入本地文件取得媒体与成果；不承诺自动同步或 iOS 首轮独立批处理。

界面主题为 Liquid Glass。保留 macOS 15 和后续 iOS 18 基线，系统 26 及以上使用原生玻璃，旧系统使用原生材质。导航和控制层使用玻璃，内容和字幕编辑保持可读。优先系统容器和控件，减少自定义布局与视觉效果层。

## 实现约束

禁止过度安全设计。当前个人工作流不需要账户、权限角色、云端恢复协调、执行租约或通用安全策略。文件访问、密钥保存、明确失败、恢复成果和避免覆盖手工校对按实际需求保留。

媒体检查避免在选择、确认、打开和播放各阶段重复做整文件哈希；缓存已取得的媒体信息，在来源变更、实际重新关联或恢复处理需要时验证身份。实现保留简单、可解释的文件访问和处理状态，不增加没有使用场景的抽象。

## 执行顺序

Task 模型、本地存储与旧数据迁移 → 原生任务列表和创建参数 → 本地音视频与音轨 → 顺序队列与分段恢复 → 翻译 → 媒体详情播放校对 → 导出与 Mac 验收 → iOS 原生播放校对。

具体条目、前置和状态以 [GitHub Project](https://github.com/users/yamakze/projects/1/views/1) 为准。需求边界见 [RFC](../RFC/voxline-v1.md)。
