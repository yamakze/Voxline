# ADR-0010：检查点与编辑成果在同一 Task 中提交

状态：已接受。

推理缓存可被清理，成功返回的数组也不能代表成果已保存。若检查点与字幕另存两份文件，崩溃可能留下互相不一致的完成标记和编辑内容。

采用单一 Task 文档，在单媒体条目内保存处理检查点、原始证据和可编辑字幕。每次完成分块或批次都验证并原子写入同一文件，成功后才向界面发布。保存和读取验证结构及状态，不重复切分已经提交的识别证据。此选择扩展 [ADR-0005](0005-task-document-format.md) 的 Task 格式。

原始切分与当前校对分别保留。已提交结果不可被重试覆盖；翻译使用发送时的文本、版本和译文快照，在提交时保护最新编辑。恢复使用冻结参数、实际媒体与提取范围，跳过完整提交的工作；单进程顺序执行由队列负责，不建立跨设备租约或云冲突协议。

原始切分及翻译输入描述过去的处理，不以当前字幕 ID 集合验证历史。当前字幕可增删、校时、拆分及合并；历史输入中已删除的字幕仍可读取，恢复计划只复用与当前字幕匹配的请求，迟到响应不能重新创建已删除的句子。两种数据保持在同一原子文档中，使用户编辑独立于机器初稿而不丢失识别恢复能力。编辑撤销只恢复字幕，保留最新检查点。

界面与后台提交共用任务库中的已提交任务，编辑界面保留独立草稿。编辑也先保存再发布，避免写入失败时界面或后台把草稿当成已保存成果；读写和校对冲突传播为明确错误，失败保留草稿和最后成功文件，修复后可重试。

临时服务错误采用有限重试，耗尽后暂停翻译并保留断点。自动等待与人工继续属于同一批次生命周期；暂停区别于永久错误和完成成果，恢复沿用冻结参数并保护校对。这样服务不可用时仍能使用已有字幕，且不会重新转写或覆盖成功译文。

已完成识别只把原始段、词时间、来源参数与切分成果保留在 Task，解码窗口及重复云响应留在设备诊断缓存。失败和取消记录仍包含窗口、词元及云识别结果，使缓存清理和跨设备交接不丢失未完成恢复来源。编码和读取均规范化已完成快照，采用紧凑 JSON；不把恢复必须的数据移到可清除缓存。此选择保留原子文档的一致性，同时减少长期编辑和同步的重复数据。

当前字段、状态与执行边界统一见 [架构](../architecture/README.md#处理检查点与恢复)，验收结果见 [Project](https://github.com/users/yamakze/projects/1)。
