# 代码品味与模块组织诊断

审查范围为任务准备、队列生命周期、服务配置、模块职责与本地化构建。当前实现规则见 [架构边界](../../architecture/README.md)，治理与验收由 GitHub Project 的 VXL-059 跟踪。编译核验材料保存在 tmp/code-taste。

## 诊断

六个模块的依赖方向合理，SwiftPM 与 Xcode 使用同一职责边界。主要维护成本来自页面持有业务操作、重复初始化执行状态、旧配置兼容与旧领域命名，适合在现有模块内收敛。

任务准备的草稿、前置检查、媒体导入与提交由共享 Session 承担，视图保留平台布局、弹窗和实际保存入口。队列的普通处理与重译共用执行生命周期，媒体顺序与待执行集合分别表达。原生文件操作、Keychain 回滚、迟到结果检查与持久恢复有明确用途，不能按代码长短移除。

## 独立意见核定

| 审查意见 | 核定与取舍 |
| --- | --- |
| 表单草稿模型 | 成立。TaskConfigurationSession 隔离业务草稿和操作，页面共享同一状态。抽取以草稿生命周期与媒体访问为边界，保留实际保存回调。 |
| 本地化轻量包装 | 未采用。自定义函数接收 literal 时，当前 Swift 编译器不会提取该键；继续使用原生 String(localized:bundle:) 保留插值类型与编译核查。 |
| 全局错误映射 | 未采用。模块已有强类型错误与本地化说明，统一映射会复制枚举分支，并削弱具体诊断。拖放读取错误应在真实发生处反馈，系统与服务的原始原因保留。 |
| 全局视觉度量令牌 | 未采用。现有共享原生材质组件与平台主题已有归属；不同布局中的相同数字不能证明相同设计语义。局部度量继续由负责组件维护。 |
| 检查点提交协议 | 未采用。队列使用读取、占用保护、提交与发布等完整任务库语义，单一提交协议不能消除这些依赖；现有核心测试已经验证真实文件持久化与恢复。 |
| 统一平台任务门面 | 未采用。两端已共享 TaskLibrary 和队列；Mac 最近文档与 iOS 独立导入、后台限时执行具有不同生命周期。对称门面会增加转发层。 |
| SwiftPM 添加 iOS 专属测试 | 不成立。当前 SwiftPM 面向 Mac；iOS 测试包含 UIKit 与平台后台 API，加入 Mac 清单不能验证 iOS。共享业务由 SwiftPM 测试，iOS 原生入口由 Xcode 模拟器测试。 |
| 模块各自维护资源 | 保留。资源与错误归实际负责模块，应用页面与导航文案归 App，不建立全局资源模块或跨模块文案分发表。 |
| 所有错误解释移至 App | 未采用。底层错误是现有能力 API 的组成部分，也由工作流持久失败状态使用；搬迁会扩大 App 对底层错误分支的依赖，增加重复维护。 |
| String Catalog | 暂缓。当前 SwiftPM 实测仅复制 xcstrings，不生成 lproj 表，直接替换会破坏 Mac 与命令行测试的本地化。重启条件是 SwiftPM 原生编译支持，或明确需要 Catalog 编辑能力，并交付统一的资源生成流程；不能同时手工维护 Catalog 与 strings。 |

## 包内组织

Workflow 的 Library 负责文档与资源清理，Queue 负责执行调度，Pipelines 负责外部处理边界，Sync 负责同步协调。Translation 内部按 SubtitleTranslation、CloudTranscription、Services 区分功能。App 的 Composition 保存共享实例接线，Translation 保存 Apple 会话与翻译执行接线。物理 Target 与依赖方向保持六模块划分。

领域错误采用 DomainValidationError；媒体访问接口使用 mediaID，设备书签的既有固定编码键不因参数改名变化。服务读取使用当前明确字段，初始化默认值只用于创建新配置；不保留明文密钥迁移或旧字段缺省读取。
