# Voxline 发布前代码质量诊断

审查基于当前源码及独立审查意见。当前实现规则见 [架构边界](../../architecture/README.md)，执行与验收记录见 GitHub Project 的 VXL-059。原始审查材料与测量日志保存在忽略的 tmp/release-final。

## 诊断

模块依赖方向清晰：Core 保存业务数据与操作，Media 处理原生音视频，Translation 处理 HTTP 协议，WhisperKit 封装模型与推理，Workflow 组织处理与持久成果提交，App 管理平台交互。音频上传补齐由 Media 提供，Workflow 注入 Translation，避免协议模块承担解码职责。

处理与导出使用有界输入，播放时钟与字幕列表的观察分离，已完成检查点保持轻量摘要。质量收敛的重点是重复编码、重复列表更新、重复排版，以及原生取消回调的并发顺序。缓存、框架、统一上下文和全局常量层均需要实际使用场景，文件行数不能单独作为重构依据。

## 独立审查结论的核定

| 审查项 | 源码结论 |
| --- | --- |
| 翻译分批与提交重复扫描 | 分批按当前字幕的实际 JSON 字节一次编码、按需复用；执行复用操作内索引。批次 ID、上下文与请求容量仍以真实输入核对。 |
| 校对视图重复更新 | 同一成功快照再次经过页面观察时复用现有行；翻译缺失状态在字幕变化时计算。 |
| 烧录整片排版预检 | 实际视频绘制回调负责排版与错误传播，重复的整片预检已移除。字号收缩仍只针对当前句，缓存有界；没有证据要求改变字号算法或成品布局。 |
| 30Hz 播放时钟重绘整页 | 当前时钟仅由播放控件观察，详情观察字幕边界。边界变化触发页面求值是正常行为，不能据此判定逐帧全列表重绘。 |
| 文件展示器通知占用主线程 | 展示器回调采用串行后台 OperationQueue，原有变化 URL 合并窗口继续生效。真实文件提供器的通知压力仍需设备测量。 |
| 内封音频附件强转 | 字典类型及 CMTime 无效时返回导出错误，避免附件类型异常引发进程崩溃。 |
| WhisperKit 空窗口强解包 | 原先已有完整识别检查拒绝空窗口，空数组崩溃判断不成立；最大帧位置采用单次归约，移除临时数组与强解包。 |
| 其他强解包 | 已核对集合的字典查询、已判定存在的对象及固定 URL 常量属于明确不变量，不能一概认定为可触发崩溃。 |
| 模型输出围栏 | 单个完整围栏支持前后说明；未闭合或多个围栏明确失败，字幕 ID 完整性与非空译文保持。不能用第一个左花括号到最后一个右花括号猜测结果，避免误拼多个对象。 |
| iOS 自动跟随 | 手动及惯性滚动期间停止跟随；减少动态效果时取消跟随动画，保留原有页面布局。 |
| Translation 音频解码 | 音频采样读取、WAV 格式化与静音补齐归属 Media，协议选择仍归属 Translation。 |
| 两端任务库适配不同 | iOS 的后台执行与独立导入副本、Mac 的系统最近文档具有实际差异；共享 TaskLibrary 与处理队列已经承载共同业务。无需再建立宿主上下文层。 |
| 配置视图与常量集中 | 配置视图仍较大，但模型、服务、参数、翻译表单已有共享组件。拆分须对应稳定职责，避免只追求 300 行目标；常量保持在实际负责模块。 |

## 保留的性能风险

### 启动与同步迁移读取

TaskLibrary 初始化及同步目录切换仍使用即时交接，枚举、读取与解码发生在应用线程。显式刷新已有后台读取，并保护读取期间的新编辑、删除、处理与目录切换。大量任务下的启动等待风险成立，但尚未测得冷启动超时或系统看门狗终止，不能直接给出严重卡顿或崩溃结论。

进一步异步化应同时处理首屏加载状态、同步恢复顺序及打开任务的时机，覆盖真实重启与损坏文档恢复；不能只替换一处调用并引入空列表与加载完成之间的竞态。

### 云端写入协调

SharedTaskDocuments 的原生协调写入与版本处理仍遵循顺序保存约定。文件提供器等待可能阻塞调用线程；本地成果已先原子保存，云端失败保留待发布与恢复记录。后台写入属于独立的持久化契约调整，需要明确完成、取消、关闭同步及冲突恢复顺序。当前测量不包含真实两设备 iCloud 争用，不能以静态代码推断等待时长。

### 原生媒体处理与真机负载

转写推理、视频解码和视频编码本身是主要计算负载。消除重复工作能减少额外开销，算法或局部规划耗时不能换算为整机 CPU 的同比降幅。真实长视频、两设备同步以及 iPhone 播放中大幅滚动的表现应按设备分别核验。
